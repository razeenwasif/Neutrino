Neutrino Status & Plan

Where Neutrino stands, the order we build the rest in, how the pieces fit, and how to run it. Neutrino is a self-hosted replacement for the parts of GitHub you pay for: repositories, branches, pull requests, diff review, CI/CD and secrets. A Rust engine reads git in-process with gitoxide; SwiftUI apps show it; the server and CI run on build-server, with jobs in Graviton containers. Each step's status updates here as it lands.

Architecture

How Neutrino fits together

One daemon binary in two roles. On workstation it's the workstation: working copies, history and diffs, all local and offline. On build-server, the always-on Mac my-server, it's the server: hosted repos, pull requests, CI and secrets, with every push copied back to GitHub. Storage stays plain git, so every editor and tool keeps working.

Storage
Plain git, read in-process
Built

No new VCS format: repos stay git, so editors, scripts and GitHub itself still work and you can leave any time. The engine opens repos with gitoxide and never forks git for reads; packs are memory-mapped and each repo's handle is kept open.

History
The graph is laid out in the engine
Built

The walk is newest first by commit time; each row carries its lane and the segments above and below the dot, coloured by lane. The client only draws, so the app, ntr log and later the phone share one layout.

Diffs
Histogram lines, then words
Built

imara-diff's histogram algorithm with git's hunk sliding. Inside each changed block, removed and added lines pair up, and pairs that share at least 40% of their visible text are diffed again by word. Results are cached by both blobs' ids, so they never go stale.

→ {"id":14,"method":"file_diff","params":{"repo":"flux","sha":"f85c23b","path":"Cargo.lock"}} ← {"id":14,"type":"file_diff","data":{"additions":4,"deletions":2,"hunks":[…]}} → {"id":15,"method":"cancel","params":{"id":13}} ← {"id":13,"type":"cancelled"}
Browsing
Files at any commit, on either machine
Built

The Code page lists a directory at a branch or tag, then asks for the newest commit touching each entry (first-parent, at most 2,000 commits back), the README and an overview: commit and contributor counts, files, and languages by extension, leaving vendored and generated code out. Files come back as text up to 1 MiB. Protocol 8; an older server gets a plain message.

→ {"id":7,"method":"tree","params":{"repo":"flux","rev":"main","path":"src"}} ← {"id":7,"type":"tree","data":{"commit":"…","path":"src","entries":[…]}}
Working copy
Writes go through git's own rules
Built

Status is read in-process with gitoxide. Staging, partial staging (a patch built from the picked lines, applied with git apply --cached), commits and branch changes run the stock git binary, as the architecture doc allows, so hooks, signing and config behave exactly as in a terminal.

Known gaps

Rough edges in what's built.

  • Deep paging re-walked history
    Fixed

    Each page used to walk from the newest commit again. Since b45c9e1 the walk and its graph rows are kept per repository and exact tips, growing by doubling: scrolling 201 pages of a 25,000-commit history went from 8.7 s to 0.36 s, and a page 20,000 deep from 91 ms to 0.5 ms. Searches still walk.

  • The pairing and publish sheets hadn't been seen
    Fixed

    Seen on 20 Nov, with the Secrets screen and a run approved from the app (b16f719 has what looking found). The window still stopped being capturable twice after a while, until the app restarted; whether that's the app or macOS isn't known.

  • No way to delete a hosted repo
    Fixed

    ntr unhost NAME --yes, or "Delete from build-server…" on a hosted repo's menu in the app (b45c9e1, ab89489). The repo moves to ~/.neutrino/deleted/, nothing erased, and it's refused while CI runs. Its pull requests and runs stay in the database, so a new repo with the same name would show them.

  • Deploys built from the working tree
    Fixed

    scripts/deploy-server.sh used to build whatever was in the checkout, uncommitted work included; on 20 Nov that sent another session's unfinished mirror change to build-server for a minute. Since efb2994 it builds a clean worktree of a commit, and ntr info names the commit that runs.

  • The Code page's commit bar is the repo's
    Open

    Inside a folder, the bar above the files still shows the newest commit of the whole branch, not of that folder. Each row's own last commit is right.

  • The menu bar icon hasn't been seen in place
    Check

    The glyph and the panel were checked in a preview window. A menu bar manager on workstation hides new items behind its arrow, so the icon itself hasn't been looked at in the bar.

  • Line staging skips git's clean filters
    Open

    Picked lines are taken from the working tree's bytes as they are, so files that rely on LFS or CRLF conversion should be staged whole. Whole-file staging goes through git add and is unaffected.

  • The watcher skips build folders by name
    By design for now

    target, node_modules, .build, DerivedData and a few others are ignored by name, not by reading .gitignore. A tracked file inside such a folder won't trigger a refresh until something else does.

  • No syntax highlighting in diffs
    Done

    Tree-sitter parses 10 languages in neutrino-diff (Rust, Swift, TS/JS, Python, JSON, TOML, YAML, Bash, Markdown), cached per blob/content hash and rendered with Stratus T3 colors in NeutrinoMac and NeutrinoIOS.

  • Merge commits show the first parent only
    By design for now

    A merge's file list and diffs compare with its first parent, like GitHub. A combined view (what the merge itself resolved) would need a second diff per file.

  • The diff cache lives in memory
    Idea

    512 diffs, dropped when the daemon restarts. The design calls for an LRU on disk, which only matters once diffs are big or the daemon restarts often.

  • Partial clones can't diff unfetched files
    By design

    A blobless clone has no file contents until fetched. Neutrino says so instead of fetching behind your back.

  • Wide graphs are cut at ten lanes
    Idea

    git.git's merge-heavy branches open twenty lanes; the app draws ten and the rest are hidden. Collapsing long-running lanes, as some git clients do, would keep it readable.

Later

Ideas that aren't scheduled.

  • A shared Rust build cache (sccache)
    Idea

    The one idea from Google's ABFS worth borrowing at this size: content-addressed build caching. Rust CI jobs keep a target/ cache per repo, keyed on Cargo.lock; sccache on build-server's disk would also reuse work when the lockfile changes and across branches and repos (mamba, onyx, Neutron, flux). Needs a cache folder that outlives jobs and is shared across repos (a new kind of Neutrino cache), a Linux sccache in the containers, and a few lines per workflow. ABFS itself doesn't fit: a Linux kernel module, its own Ninja and remote cache servers, made for Android.

  • Blame and file history
    Idea

    Who changed a line and when, and a file's history across renames. gitoxide has blame; the History screen would gain a path filter.

  • Image and notebook diffs
    Idea

    Side-by-side images with a swipe, and Jupyter notebooks diffed by cell rather than by JSON.

  • A bundled daemon
    Idea

    Ship neutrinod inside Neutrino.app and have the app install the launch agent itself, as Graviton's release script does.

  • Issues and pull requests from GitHub
    Idea

    ntr import brings the code over (milestone 9); a repo's open issues and pull requests still live only on GitHub. A one-shot import of those would finish the move.

Guide

Using what's built

Everything here runs on workstation. Reads stay in-process; writes go through git.

Start in four steps

  1. Run the daemon

    scripts/dev-neutrinod.sh builds and runs it in a terminal. scripts/install-launch-agent.sh runs it at login instead.

  2. Register a repo

    ntr repo add ~/code/myrepo, or ⌘O in the app. Any folder inside a working copy works; nothing in it changes.

  3. Open the app

    cd apps && xcodegen generate && open Neutrino.xcodeproj, then run NeutrinoMac. It connects on its own once the daemon is up.

  4. Work

    Code shows a repo's files and README; Changes stages and commits; History shows the graph; Branches switches, creates, renames or deletes branches. Repos on build-server sit under the server in the sidebar.

Committing

Pick lines

In Changes, pick a file, then click lines in its diff. Stage N lines (⌘⇧S) stages just those; in the staged view the same button unstages them. Each hunk header has its own Stage hunk button.

Safe discards

Discarding keeps a copy of the file in the repo, listed in ~/.neutrino/discarded.log; git cat-file -p <sha> gets it back. Untracked files go to the Trash.

Real git

Commits, switches and branch deletes run the git binary, so hooks, signing and your identity apply, and git refuses what it always refuses. A hook's output shows under the commit.

Day to day with ntr

Every repo's origin is its hosted copy on build-server, and GitHub is a mirror that build-server updates after each push. Use ntr where you used git: what ntr doesn't know runs as git, and server commands go to build-server over SSH.

  1. Start from main

    ntr switch main, ntr pull, then ntr switch -c fix-login.

  2. Work and commit

    ntr status, ntr diff, ntr add -p or the app's Changes screen, then ntr commit -m "Fix the login redirect".

  3. Push to build-server

    ntr push -u origin fix-login. The push starts the branch's workflows, and build-server copies the branch to GitHub.

  4. Open a pull request

    ntr pr create fix-login --title "Fix the login redirect", then ntr pr show 7 for its files, commits and whether it merges.

  5. Watch the checks

    ntr runs --pr 7, then ntr run logs 12 -f. If a check fails, fix it, commit and ntr push: that adds a version to the pull request and runs the checks again.

  6. Merge

    ntr pr merge 7 -s squash -d squashes, merges and deletes the branch. Main's push workflows run, deploys included.

  7. Approve a deploy

    ntr inbox lists what's waiting; ntr run approve 13 lets it go, or approve it on the iPhone with Face ID.

  8. Tidy up

    ntr switch main, ntr pull, ntr branch -d fix-login.

Code

ntr switch -c fix, ntr status, ntr commit -am "…", ntr push -u origin fix. Never push to the github remote; build-server copies there.

Review and CI

ntr pr create fix --title "…", ntr pr list, ntr pr merge 3. ntr runs, ntr run logs 12 -f, ntr run approve 12 for a protected environment.

Secrets

ntr secret set NAME --env production < file, ntr var set, ntr env list. Values stay on build-server, in the vault.

The mirror

ntr mirror shows how each repo's last copy went. If someone pushed to GitHub, the mirror refuses to overwrite it: ntr pull github main, then ntr push, and the next copy goes through.

A new repo

ntr host NAME, then ntr mirror set -r NAME with its GitHub URL. Clone it anywhere with ntr clone ssh://my-server~/.neutrino/repos/NAME.git.

Working on build-server from workstation

Github and Research live on build-server, the Mac my-server. workstation, the MacBook, is the window onto them: editors, Claude, agy, builds and ntr all run on build-server over SSH, so workstation stays light and the work is there whichever screen you sit at. kagutsuchi goes over Tailscale, so it works away from home too (my-server is the same host, kept because every repo's origin uses it).

  1. Connect

    ssh kagutsuchi, then cd ~/Github/Applications/Neutrino. If Tailscale is off at home, ssh kagutsuchi-lan.

  2. Edit

    nvim there, with the same config and plugins. Proton can't open files over SSH yet, so Proton is for the few repos kept on workstation.

  3. Claude

    In the Claude app, start a new session, pick SSH in the place picker, add kagutsuchi and choose the project folder; save it as a preset to come back to. In a terminal, claude after ssh kagutsuchi.

  4. Antigravity

    agy after ssh kagutsuchi and cd into the project. It has no SSH mode of its own; it runs where the files are.

  5. Push and CI

    ntr and git work in repos on build-server as on workstation; there, my-server is build-server itself.

  6. Files you collect

    relay copies workstation's Downloads, Documents, Desktop and Pictures to the same folders on build-server each night at 2:00 (never deleting, never overwriting newer files there); delete them from workstation once they're across. relay diff shows what's waiting, relay sync sends it now.

Kept on workstation

Xcode can't open a project over SSH, so the Apple apps (Neutrino's, Graviton's, boxtube, Fairy's iPhone app) keep a clone on workstation for the Simulator and running the Mac apps. origin is on build-server either way.

Fairy

Fairy's desktop app runs on build-server under its keep-alive agent and finds projects at ~/Github there, so she needs no SSH setup.

Not yet

The Mac app's Changes screen reads working copies through workstation's daemon, so it doesn't see work on build-server; use ntr status and ntr diff there.

When something's off

Demo data

The pill at the top right says Demo data when the app can't reach neutrinod. Start the daemon; the app notices within four seconds.

Socket path

Unix socket paths are limited to 104 bytes. The default ~/.neutrino/neutrinod.sock is fine; set NEUTRINO_SOCKET to something short if you move it.

Live view

Neutrino watches each registered repo and refreshes within a fraction of a second. Changes inside build folders such as target and node_modules are ignored on purpose. ⌘R reloads everything.
